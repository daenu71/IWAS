===========================================

Zusammenfassung
---------------

---------------------------

Ergebnis:

Normierung
----------
Bewertung:
- Die Normierung waere grundsaetzlich kompatibel.
- `reconstruct_xy()` normiert ueber `_normalise_xy(...)`.
- Der IBT-Extraktor verwendet fuer `track_road_geometry.json` ebenfalls `_normalise_xy(...)`.
- Damit ist die wahrscheinlichste Ursache nicht die Normierung, sondern das fehlende Laden und fehlende Rendering.

Code-Auszug Normierung:

```python

418:             return _normalise_xy(x, y)
429:             return _normalise_xy(x, y)

976:     """Normalise *x* and *y* to [0, 1] preserving aspect ratio."""
985:     scale = max(x_range, y_range)
986:     xn = (x - x_min) / scale
987:     yn = (y - y_min) / scale
988:     return np.column_stack([xn, yn])
```


Wahrscheinlichste Ursache
-------------------------
Die wahrscheinlichste Ursache ist eine Kombination aus zwei Blockern:

1. Es existiert aktuell keine `track_road_geometry.json` im konfigurierten Storage, daher gibt es zur Laufzeit nichts zu laden.
2. Selbst wenn die Datei vorhanden waere, wuerde sie derzeit nicht sichtbar werden, weil:
   - `LapViewModel.load()` kein `track_road_geometry` laedt,
   - `LapViewModel` kein entsprechendes Feld besitzt,
   - `render_trackmap()` keinen `road_geometry`-Parameter und keinen Renderpfad hat,
   - `render_corner_zoom()` das Road-Band explizit noch als "future" / nicht implementiert markiert.

Fazit:
Story 3.1 / 3.3 sind im aktuellen Code nicht vollstaendig umgesetzt oder nicht in den aktiven Lade-/Renderpfad integriert.
